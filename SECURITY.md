# Security Policy

This is the default policy for repositories in the Sorogate organization that do not have their own `SECURITY.md`.
The `sorogate` repository does have its own, and it lists what is in scope for the contract.

## Reporting a vulnerability

Please do not open a public issue for a security problem. Use GitHub's
[private vulnerability reporting](https://github.com/Sorogate/sorogate/security/advisories/new) and say which
repository your report is about. If that page is not available to you, open a public issue that says only
"I have a security report" and a maintainer will arrange a private channel. Do not put details in the issue.

## Status and scope

These projects are early and **have not been audited**. They are meant for Testnet. Do not use them with real value.

## Response

These are small projects. A maintainer will acknowledge a report as soon as they can and say plainly what they
can and cannot do. No bug bounty is offered.
